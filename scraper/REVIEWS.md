# 리뷰 — 세되, 옮기지 않는다

페이지는 리뷰를 **인용하지 않습니다.** 대신 "어떤 이야기가 몇 %에서 나오는가"만 싣고,
실제 글을 읽고 싶은 사람은 채널 링크로 원 사이트에 보냅니다.

```
수집 → 정제 → 주제 집계 → 총평(비율)만 내보내기
                              ↓
                    본문은 저장도 게시도 하지 않음
```

이 선택 하나로 문제 대부분이 사라집니다.

| | 인용 방식 | 지금 방식 |
|---|---|---|
| 저작권 | 본문에 권리 존재 | **사실 통계는 표현이 아님** |
| 이용약관 | 재게시 금지 조항에 걸림 | 게시물이 없음 |
| 번역 비용 | 리뷰당 과금, 수십만 자 | **0원** (라벨이 고정 사전) |
| 번역 품질 | 오역이 그대로 노출 | 사람이 쓴 라벨 19개 |
| 개인정보 | 작성자 표기 필요 | 작성자를 아예 다루지 않음 |

## 지금 동작하는 것

- **수집** — `LdReviewSource`(schema.org Review), `JsonReviewSource`(내부 JSON).
  `base.Channel`을 상속해 robots.txt 확인·레이트리밋·캐시를 그대로 씁니다.
- **정제** — 대가성 후기 제외(체험단·협찬·원고료 정규식), 12자 미만 제외,
  본문 해시로 중복 제거, 별점 4점 이상을 긍정으로 분류.
- **집계** — `reviews.THEMES` 19개 주제(수분 지속·백탁 없음·용기·펌프·자극…)에
  한국어 키워드를 걸어 버킷별 언급 비율을 셉니다.
- **출력** — `rvi` 필드. 페이지가 이걸 발견하면 데모 수치 대신 실제 비율을 그립니다.

```json
"rvi": { "n": 1184, "share": 89,
         "pos": [{ "ko": "수분 지속", "en": "Hydration that lasts", "pct": 57 }],
         "neg": [{ "ko": "용기·펌프", "en": "Packaging", "pct": 22 }] }
```

## 실제로 붙이려면 남은 일

### 1. 접근 경로 — 여전히 첫 관문

집계만 한다고 수집이 허용되는 건 아닙니다. 자동 수집 자체를 금지하는 약관이 많습니다.

1. **공개 구조화 데이터** — 상품 페이지에 `schema.org/Review`를 심어둔 몰. 검색 노출용으로
   스스로 공개한 데이터라 가장 무난합니다.
2. **제휴 / 오픈 API** — 정공법. 실서비스로 갈 거면 여기입니다.
3. **내부 JSON** — 개편마다 깨지고 봇 차단이 걸린 곳이 많습니다.

**차단은 우회하지 않습니다.** robots.txt가 막거나 403이면 그 채널은 대상에서 뺍니다.
이 수집기에는 우회 수단이 없고 넣지 않을 겁니다.

### 2. 채널별 상품 ID — 유일하게 남은 미구현

`JsonReviewSource._goods_id(url)` 이 비어 있습니다. 몰마다 URL에서 상품 번호를 뽑는
규칙이 달라, 붙일 채널이 정해진 뒤 쓰는 게 맞습니다. `adapters.py`의 각 어댑터가
`RawItem.extra["goods_id"]`를 채우도록 확장하는 편이 더 깔끔합니다.

### 3. 주제 사전 키우기

여기가 품질의 대부분입니다. `reviews.untagged()`가 어떤 주제에도 안 걸린 리뷰를
뽑아줍니다. 이걸 주기적으로 훑으며 `THEMES`에 키워드를 더하세요.

```bash
python run.py --channels oliveyoung --reviews -v   # 미분류 리뷰가 로그에 남습니다
```

`translate.py`는 이제 **게시물에 쓰이지 않습니다.** 미분류 한국어 리뷰를 훑어보며
사전을 늘릴 때 보조로만 씁니다(`--engine deepl`). 용어집·캐시·사후 교정은 그대로 살려뒀습니다.

### 4. 표본 수 표시

언급 비율은 표본이 작으면 흔들립니다. 리뷰 30건 미만이면 비율 대신 "표본 부족"으로
표시하는 처리가 필요합니다 — 아직 없습니다.

## 실행

```bash
pip install -r requirements.txt
python run.py --channels oliveyoung --reviews --out ../data/catalog.json
```

## 권고

포트폴리오라면 지금이 적정선입니다. 화면에 데모 수치임을 밝혔고, 실데이터가 들어오면
그대로 동작합니다. 실서비스라면 **1번(접근 권한)부터** 푸세요 — 2·3번은 그다음 문제입니다.
