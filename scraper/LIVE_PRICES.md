# 진짜 가격을 넣는 법

지금 이 빌드는 **가격 데이터 없이** 나갑니다. 화면의 숫자는 레이아웃을 보여주기 위한
표본이고, 헤더 배지가 `SAMPLE DATA`로 그 사실을 계속 알립니다.

실제 가격을 넣으면 배지가 `NAVER SHOPPING API`로 바뀌고, 같은 화면이 진짜 숫자를 그립니다.
**불법도 회색지대도 아닙니다** — 네이버가 공식으로 공개한 API를 쓰는 경로입니다.

---

## 왜 이 방식이 문제가 없나

| | |
|---|---|
| **가격은 사실입니다** | 사실에는 저작권이 없습니다. 다나와·에누리·네이버쇼핑이 이 사업을 합니다 |
| **공식 API를 씁니다** | 긁는 게 아니라 네이버가 제공하는 창구로 요청합니다 |
| **정확한 견적을 주장하지 않습니다** | 가격대(범위)와 상대 순위만 싣습니다 |
| **확인은 사용자가 합니다** | 매장 링크를 눌러 실제 가격을 직접 봅니다 |

페이지가 매장별 정확 금액을 **일부러 표시하지 않는** 이유가 여기 있습니다. 그건 시간이
지나면 반드시 틀리는 주장입니다. 대신 `₩53,000–55,000` 같은 범위와 `baseline / +2% / +4%`
같은 상대 위치를 보여줍니다. 둘 다 하루이틀 지나도 대체로 유효합니다.

---

## 20분이면 됩니다

### 1. 네이버 개발자 등록 (5분)

1. <https://developers.naver.com/apps/#/register> 접속
2. 애플리케이션 등록 → **검색** API 선택
3. 발급된 Client ID / Secret 복사

무료입니다. 하루 25,000회까지 호출할 수 있습니다.

### 2. 실행 (10분)

```bash
cd scraper
pip install -r requirements.txt

export NAVER_CLIENT_ID=발급받은_아이디
export NAVER_CLIENT_SECRET=발급받은_시크릿

python run.py --channels naver --out ../data/catalog.json
```

`items[].lprice` / `hprice` 가 그대로 가격대가 되고, `mallName` 이 판매처 이름이 됩니다.
파이프라인이 브랜드명을 통일하고 동일 상품을 묶은 뒤 `data/catalog.json` 을 씁니다.

```json
{ "source": { "mode": "live", "label": "Naver Shopping API",
              "when": "2026-08-24 10:32 KST" },
  "products": [ { "i": 1, "b": "ANUA", "n": "…", "o": [["쿠팡", 17900], …] } ] }
```

### 3. 페이지에 연결 (5분)

`index.html` 안의 인라인 데이터 블록을 위 파일 내용으로 바꾸면 됩니다.

```js
const DATA_SOURCE = { … };   // ← catalog.json 의 source
const P = [ … ];             // ← catalog.json 의 products
```

`DATA_SOURCE.mode` 가 `live` 가 되는 순간 페이지가 알아서 바뀝니다.

- 헤더 배지 `SAMPLE DATA` → `NAVER SHOPPING API` (민트색)
- 경고 문구가 "표본입니다" → "언제 수집했고, 매장은 매일 바뀝니다"로 교체
- 상세 모달 하단에 수집 시각 표기

---

## 다른 채널을 더 붙이려면

네이버 API 하나로 이미 여러 판매처의 가격대가 들어옵니다. 그 이상이 필요하면:

1. **쿠팡 파트너스 API** — 제휴 가입 후 상품·가격을 정식으로 받습니다
2. **각 몰의 제휴 프로그램** — 올리브영·컬리 등은 개별 문의가 필요합니다
3. **공개 구조화 데이터** — 상품 페이지에 `schema.org/Product`를 심어둔 몰. `JsonLdChannel` 이 읽습니다

**차단은 우회하지 않습니다.** `robots.txt` 가 막거나 403이 오면 그 채널은 대상에서 뺍니다
(`base.Channel.allowed`). 우회 수단은 이 수집기에 없고, 넣지 않을 겁니다.

## 신선도 관리

가격은 하루면 바뀝니다. 실서비스로 쓸 거라면:

- **수집 주기** — 하루 1회면 충분합니다. `source.when` 이 화면에 그대로 표시됩니다
- **오래된 데이터 처리** — 수집 후 3일이 지나면 가격대를 흐리게 처리하거나 감추는 편이 맞습니다 (아직 미구현)
- **표본 부족** — 판매처가 1곳뿐이면 "범위"라고 부를 수 없습니다. 이때는 상대 순위를 감춰야 합니다 (아직 미구현)
